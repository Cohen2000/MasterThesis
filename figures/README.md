## `pipeline_updt.png` — superseded, kept for provenance

This figure was produced with an image model earlier in the project. It is
retained because it appears in earlier notes, but it should not be used in the
thesis. Checked against the code on 2026-08-25, six of its statements are
wrong:

| Shown | Actual | Where to check |
|---|---|---|
| three windows `W1..W3` | `W = 5`; the target is `rho_k` for `k = 2..5`, which three windows cannot support | `HEADLINE_W` in `src/census.py`; the DEFINITIONS block of `results/llm_v2/prompts.jsonl` |
| `rho_k = ... / all observed edges` | the denominator is every *pair* of the **full** network with `K >= 1`, not the sampled pairs | the prompt states it explicitly: "Targets, always defined over ALL pairs of the full network with K >= 1 (not only the pairs you were shown)" |
| "edges" | the unit is a node *pair* (dyad); `spans()` warns about exactly this name collision | `src/census.py` |
| an invented feature table (`edge revisit rate 0.18`, `return time 6.8`, ...) | the estimator receives an `(n, window-mask)` histogram of observed pairs; no such feature vector exists anywhere in the pipeline | `results/llm_v2/prompts.jsonl` |
| `XGBoost` as the supervised probe | scikit-learn `ExtraTreesRegressor` and `RandomForestRegressor`; xgboost is not a dependency | `src/evaluate_design_baselines.py`, `src/bias_identifiability.py`, `requirements.txt` |
| three walk strategies, "x3 one per walk strategy" | seven mechanisms in two families: five walk-based and two non-walk. The frozen LLM suite uses three of them, and one of those three is a non-walk panel | `strategy` column of `results/benchmark_v2/results/predictions.csv.gz`; `results/llm_v2/llm_cases.csv` |

A seventh point is a simplification rather than an error: the figure labels the
model box "Zero-shot LLM", but the suite also contains a `disclosed_examples`
condition (84 of the 420 frozen prompts), so it is not purely zero-shot.

The first two matter most. Three windows make the `k = 4` and `k = 5` levels of
the target undefined, and a denominator of "observed edges" describes a sample
property — which is the opposite of the quantity the whole project is trying to
estimate.
